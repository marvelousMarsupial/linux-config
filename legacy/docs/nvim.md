# Neovim

Custom neovim configuration using lazy.nvim for plugin management.

## Requirements

- Neovim 0.11+ (uses new `vim.lsp.config` API)
- Node.js (for Mason LSP server installs)
- ripgrep (for Telescope grep)
- A Nerd Font (for icons)
- build-essential (for telescope-fzf-native compilation)

## Structure

```
stow/nvim/.config/nvim/
├── init.lua                  # Entry point (loads config/)
├── lua/
│   ├── config/
│   │   ├── lazy.lua          # Plugin manager bootstrap
│   │   ├── keymaps.lua       # Custom keybindings
│   │   └── options.lua       # Vim options
│   └── plugins/
│       ├── colorscheme.lua   # Theme (generated by theme script)
│       ├── telescope.lua     # Fuzzy finder
│       ├── treesitter.lua    # Syntax highlighting
│       ├── lsp.lua           # Language servers
│       ├── cmp.lua           # Completion
│       ├── format.lua        # Format-on-save (conform.nvim)
│       ├── obsidian.lua      # Note-taking
│       ├── editor.lua        # Editor enhancements
│       ├── ui.lua            # UI components + zen mode
│       ├── smart-splits.lua  # Tmux integration
│       ├── fterm.lua         # Floating terminal
│       └── markdown.lua      # Markdown rendering
```

## Theme Integration

Colors are controlled by the [[theme]] system.

### How It Works

1. `theme apply <scheme>` writes `colorscheme.lua` with Base16 palette
2. Theme script sends reload command to all nvim instances via socket
3. Nvim re-sources colorscheme.lua

### Scheme Types

**Native plugins** (tokyonight, onedark):
- Theme system writes `vim.cmd("colorscheme tokyonight")`
- Plugin handles all highlighting

**Base16 schemes** (gruvbox, catppuccin, kanagawa, etc.):
- Theme system writes full Base16 palette to mini.base16
- Additional treesitter highlight overrides for vibrant syntax
- Transparency applied to match foot terminal

### Transparency

All schemes use transparent backgrounds:
- Normal, NormalNC, SignColumn, LineNr → transparent
- NormalFloat → slightly visible (`base01`)
- StatusLine → subtle (`base01`)

## Zen Mode for Vault Notes

Files in `*/vault/*.md` automatically hide the statusline for distraction-free writing.

- Entering a vault markdown file: statusline hidden (`laststatus=0`)
- Leaving: statusline restored (`laststatus=3`)

This applies to both `~/vault/` and `~/linux-config/docs/`.

## smart-splits

Seamless navigation between nvim splits and tmux panes.

### How It Works

1. You press `Alt+h` in nvim
2. smart-splits checks if at left edge
3. If at edge: passes key to tmux
4. tmux then moves to left pane

Same keys work everywhere: `Alt+hjkl` for movement, `Alt+HJKL` for resize.

### Configuration

```lua
at_edge = "stop"              -- Don't wrap, let tmux handle
multiplexer_integration = "tmux"
```

## Socket for Theme Reload

Nvim listens on a socket for theme reload commands:

```
$XDG_RUNTIME_DIR/nvim.<pid>.sock
```

Theme script finds all sockets and sends:
```bash
nvim --server $sock --remote-send ':source ~/.config/nvim/lua/plugins/colorscheme.lua<CR>'
```

## Troubleshooting

### LSP Not Starting

```vim
:LspInfo              " Check status
:Mason                " Check server installed
:LspLog               " View errors
```

### Treesitter Errors

```vim
:TSUpdate             " Update all parsers
:TSInstall <lang>     " Install specific parser
```

### Completion Not Working

Check sources are loaded:
```vim
:lua print(vim.inspect(require('cmp').get_config().sources))
```

### Theme Not Applying

1. Check colorscheme.lua was updated by theme script
2. Ensure socket exists: `ls $XDG_RUNTIME_DIR/nvim.*.sock`
3. Manual reload: `:source ~/.config/nvim/lua/plugins/colorscheme.lua`

### Format-on-Save Not Working

1. Check formatter is installed: `:ConformInfo`
2. Manual format: `<leader>cf`
3. Install missing formatters: `:MasonInstall stylua prettier ruff shfmt`

### Yazi Not Opening

Ensure both `yazi` and `ya` are installed:
```bash
which yazi
which ya
```
